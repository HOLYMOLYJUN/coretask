## 1. 🔴 P0 · 업무를 만든 뒤 어떤 필드도 수정할 수 없다

### 증상

업무 상세 패널이 보여주는 것: 제목 · 프로젝트 · 시작일 · 우선순위 · 기록.
이 중 **편집 가능한 것은 하나도 없다.** 상태 변경 버튼만 동작한다.

| 하고 싶은 일 | 지금 가능한가 |
|---|---|
| 제목 오타 고치기 | ❌ 지우고 다시 만들어야 한다 |
| 설명 추가·수정 | ❌ 입력란 자체가 없다 |
| 우선순위 변경 | ❌ |
| 담당자 변경 | △ 보드로 가서 드래그해야 한다 |
| 마감일 지정·변경 | ❌ **§1-A 참조 — 막다른 길이다** |

### 근거

- **US-601 AC-3**: *"상세에서 직접 상태 변경, 담당자 변경(권한 있을 때), 필드 수정이 가능하다"*
- **US-302**: Task 수정 / 삭제 — 삭제는 `bb4fb8c` 에서 구현했고 **수정은 미구현**

### 1-A. 마감일은 구조적으로 막혀 있다

가장 나쁜 형태의 결함이다 — **제품이 경고를 띄우면서 해결 수단을 주지 않는다.**

카드에는 `⚠️ 마감일 없음` 이 빨간 글씨로 뜬다 (US-402 · `is_missing_due`).
그런데 마감일 입력 팝오버는 [board-page.tsx:222](../apps/web/src/features/board/board-page.tsx#L222) 에서
**담당자가 바뀔 때만** 열린다:

```ts
if (assigneeId !== null && assigneeChanged && !task.due_date) { … }
```

내 컬럼에서 업무를 만들면 `assignee_id` 가 생성 시점부터 나다 →
담당자 변경이 영영 일어나지 않는다 → **마감일을 넣을 기회가 오지 않는다.**

유일한 우회로는 *미배정으로 드래그했다가 다시 나에게 끌어오는* 2단 드래그인데,
이걸 스스로 알아낼 사용자는 없다.

> 💡 D-021b(마감일은 배정 시점에 묻는다)는 **배정 흐름의 규칙**이지
> *마감일을 배정으로만 넣을 수 있다*는 뜻이 아니었다. 구현이 규칙을 좁게 읽었다.

### 제안

업무 상세에 인라인 편집을 붙인다. 별도 편집 모드를 만들지 않는다 —
값을 누르면 그 자리에서 바뀌고, 벗어나면 저장된다.

- 제목: 클릭 → textarea, blur 저장
- 설명: 비어 있을 때도 `설명 추가` 자리를 남긴다 (지금은 값이 없으면 영역이 사라진다)
- 마감일: 기존 `DuePopover` 재사용 — 이미 퀵칩(오늘·내일·이번주 금·다음주 금)이 있다
- 우선순위 · 담당자: select. 담당자는 Lead 권한일 때만 (US-601 AC-3)

서버는 이미 준비되어 있다 — `tasks_update` 정책, `tg_task_validate` 가 규칙을 판정한다.

## 2. 🟡 P1 · 대시보드 위젯이 하나 빠졌다

**US-701 AC-2** 는 위젯 넷을 정의한다:
`오늘 할 일` · `내 진행중 업무` · `이번주 마감` · `내 프로젝트`

실제 화면에는 **`이번주 마감` 이 없다** ([dashboard-page.tsx](../apps/web/src/features/dashboard/dashboard-page.tsx)).

마감일 관리가 이 제품의 축인데(D-021 · D-015) 그 축을 보여주는 위젯이 빠져 있다.
§1-A 를 고치면 마감일이 실제로 채워지기 시작하므로, 그때 이 위젯이 비로소 의미를 갖는다.
**§1 과 함께 처리한다.**

## 3. 🟡 P1 · 프로젝트를 만들어도 아무 데도 가지 않는다

**US-201 AC-4**: *"생성 직후 **프로젝트 개요 화면으로 이동**하고, '팀원 추가' 와 '첫 업무 만들기' 를 다음 행동으로 제시한다."*

실제로는 목록에 한 줄이 추가되고 끝난다. 방금 만든 프로젝트를 사용자가 다시 찾아 눌러야 한다.
개요 화면(**US-203**) 자체가 없다.

### 제안 (단계적)

1. **지금**: 생성 성공 시 그 프로젝트 보드로 이동한다. 한 줄이면 된다.
2. **나중**: US-203 개요 화면을 만들 때 목적지를 개요로 바꾼다.

빈 보드에는 이미 `업무 추가` 가 있고 `멤버` 버튼도 붙었으므로(`fad3e87`),
보드로 보내는 것만으로 AC-4 의 의도("다음 행동 두 개")는 거의 충족된다.
