## 1. 레이아웃 원칙

1. **화면마다 주인공은 하나다.** 배정 보드의 주인공은 카드다. 헤더·필터·사이드바가 카드보다 시각적으로 무거우면 잘못된 화면이다.
2. **정보를 카드에 넣기 전에 "이걸 보고 무슨 행동을 하나"를 묻는다.** 행동으로 이어지지 않는 정보는 상세로 내린다.
3. **파괴적 동작은 시각적으로 무겁게, 반복 동작은 가볍게.** 삭제는 확인 모달, 상태 변경은 즉시 실행 + Undo.
4. **빈 상태도 화면이다.** 와이어프레임에 반드시 포함한다 (IA §8).
5. **데스크톱 기준폭 1280px, 모바일 기준폭 390px** 로 그린다.

### 카드 명세 — 이 제품에서 가장 많이 보게 될 요소

```
┌──────────────────────────┐
│ 🔺 로그인 API 연동        │  ← 1행: 우선순위 아이콘 + 제목 (2줄까지)
│ 🟡 진행중 · 3일           │  ← 2행: 상태 뱃지 + 경과일
│ ~7/28  D-2               │  ← 3행: 마감일 + 남은 일수
└──────────────────────────┘
```

**표시하는 것 (5개로 고정)**

| 요소 | 형태 | 없을 때 |
|---|---|---|
| 우선순위 | `🔺높음` / (보통은 표시 안 함) / `🔻낮음` | 보통이면 아이콘 생략 |
| 제목 | 최대 2줄, 넘치면 `…` | — |
| 상태 뱃지 | 🔵예정 🟡진행중 🟣리뷰중 🟢완료 | 항상 표시 |
| 경과일 | `· 3일` (진행중/리뷰중만) | 당일이면 `· 오늘` |
| 마감일 | `~7/28  D-2` / `🔴 D+3` / `⚠️ 마감없음` | 배정+마감없음이면 경고 |

**표시하지 않는 것과 그 이유**

| 뺀 것 | 이유 |
|---|---|
| 담당자 아바타 | **컬럼이 곧 담당자다.** 중복이고, 카드 폭만 잡아먹는다 |
| 프로젝트명 | 프로젝트 안이라 전부 같다 (내 업무 보드에서는 **표시한다**) |
| 설명 미리보기 | 행동으로 이어지지 않는다. 상세로 |
| 댓글 수 | v1 제외. 실제로 봐야 하면 v1.1에 아이콘만 |

> ⚠️ **카드에 더 넣고 싶어지는 순간이 온다. 그때 §1-2를 읽는다.**
> "이걸 보고 무슨 행동을 하나?" 에 답이 없으면 넣지 않는다.

### 인터랙션

| 동작 | 결과 |
|---|---|
| 카드 클릭 | 우측 패널로 상세 (D-031) |
| 카드 드래그 → 다른 컬럼 | 담당자 변경. 마감일 없으면 팝오버 |
| **드래그 중** | 원본은 반투명, 드롭 가능 컬럼만 테두리 강조 |
| Member가 드래그 시도 | 커서 `not-allowed`. **미배정 컬럼 카드만** 본인 컬럼으로 가능 |
| `+ 업무 추가` | 컬럼 하단에 인라인 입력창. Enter로 생성 후 **입력창 유지** |
| 컬럼 헤더 클릭 | 그 사람 업무만 필터 (빠른 1인 보기) |

### 마감일 팝오버 (US-304 · 드롭 직후)

```
        ┌─────────────────────────────┐
        │ 언제까지?                    │
        │                             │
        │ [오늘] [내일]                │
        │ [이번주 금] [다음주 금]        │
        │                             │
        │ 📅 직접 선택                 │
        │                             │
        │           [나중에 정하기]     │
        └─────────────────────────────┘
             ▲ 드롭한 카드 바로 아래에서 열림
```

- 드롭한 카드 **바로 아래**에서 열린다. 화면 중앙 모달이 아니다 — 맥락을 잃지 않기 위해.
- `Esc` = `나중에 정하기`
- **가져가기(F5)에서는 `[나중에 정하기]` 가 없다** (US-403 AC-5)

### `완료` 컬럼 잠금 표현 🔒

**Member에게는 완료 컬럼이 잠긴 것으로 보인다** (US-501 AC-5).

```
╔══════════════════╗
║        🔒        ║   ← 점선 테두리 + 흐린 배경
║  Lead가 확정합니다 ║
║                  ║
║  ▸ 완료 12건 보기 ║
╚══════════════════╝
```

- 드래그해서 가져가면 **드롭 영역이 비활성**으로 표시되고, 놓으면 카드가 원위치 + 토스트:
  *"완료 확정은 Lead가 합니다. 리뷰중으로 올려주세요"*
- 그 프로젝트에서 내가 Lead면 **자물쇠 없이 정상 컬럼**으로 보인다.

> 💡 **컬럼을 숨기지 않고 잠근 이유:** 숨기면 "내 완료 업무는 어디 갔지?" 가 된다. 잠금 상태로 보여주면 **규칙을 학습**시키면서 완료 목록 접근도 유지된다.

```
        640px                      440px
```

**핵심 결정: 댓글과 활동 로그를 한 타임라인에 섞는다** (US-603 AC-1)

- 탭으로 나누면 *"댓글 3개"* 와 *"3일 전 상태 변경"* 의 **선후관계가 안 보인다.**
- 실제로 알고 싶은 건 *"이 업무에 무슨 일이 있었나"* 라는 하나의 이야기다.
- 활동 로그는 `⚙️` 아이콘 + 흐린 회색으로 시각적 무게를 낮춘다. **댓글이 주인공, 로그는 배경.**

**필드 편집**

- 모든 필드는 **클릭하면 그 자리에서 편집**(inline). 별도 "수정" 모드 없음.
- 권한이 없는 필드는 **드롭다운 화살표 없이 텍스트로만** 표시.
- 변경은 즉시 저장. 저장 버튼 없음.

## 10. 결정이 필요한 항목

| # | 질문 | 내 추천 |
|---|---|---|
| 1 | **사이드바 `내 업무` 뱃지 숫자의 정의** — 미완료 전체(예정+진행중)? 아니면 "오늘 할 일"만? | **`예정 + 진행중` 전체.** "오늘"로 좁히면 마감 없는 업무가 영영 안 세어진다. 다만 숫자가 20을 넘으면 압박만 되므로 `20+` 로 끊는다 |
| 2 | **완료 컬럼 잠금(🔒)을 보여줄까, 숨길까?** | **보여준다.** 숨기면 "내 완료 업무는 어디 갔지?"가 되고, 잠금은 규칙을 학습시킨다 |
| 3 | **배정 보드 컬럼 정렬을 사람 이름 가나다순으로?** | **v1은 가나다순 고정.** 단 **본인 컬럼을 미배정 바로 다음에 고정**하자 — Lead도 실무자라 자기 컬럼을 가장 자주 본다 |
