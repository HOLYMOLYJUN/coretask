## 1. IA 설계 원칙

Foundation §2에서 파생된, **이 문서에서만 쓰는 판단 기준**이다.

1. **주소가 있는 것만 화면이다.** 새로고침·공유·푸시알림 진입이 불가능하면 그건 화면이 아니라 상태다.
2. **맥락을 잃게 하지 않는다.** 보드에서 Task를 열 때 보드를 떠나지 않는다. → 패널/모달 + URL 병행 (§5).
3. **깊이는 3단계까지.** `사이드바 → 프로젝트 → 탭` 이 최대다. 그 아래는 패널로 처리한다.
4. **모바일은 축소판이 아니라 다른 내비게이션이다.** 사이드바를 햄버거로 접는 방식은 쓰지 않는다 (§6).
5. **권한 없는 리소스는 403이 아니라 404다.** "있지만 못 본다"를 알려주면 프로젝트 존재 자체가 유출된다.

## 3. 라우트 명세

### 3.1 인증 밖

| 경로 | 화면 | 접근 | 비고 |
|---|---|---|---|
| `/login` | 로그인 | 누구나 | 이미 로그인 상태면 `/` 로 리다이렉트 |
| `/signup` | 가입 | 누구나 | 〃 |
| `/invite/[token]` | 초대 수락 | 누구나 | 미로그인 → 가입/로그인 후 자동 복귀. 만료 시 안내 화면 |
| `/auth/callback` | OAuth 콜백 | — | 화면 없음 |

### 3.2 온보딩

| 경로 | 화면 | 접근 | 진입 조건 |
|---|---|---|---|
| `/onboarding/workspace` | 워크스페이스 생성 | 로그인 | **소속 워크스페이스 0개일 때 강제 리다이렉트.** 이미 있으면 `/` 로 되돌림 |

> 💡 1인 1워크스페이스(D-022)라서 이 화면은 **평생 한 번**만 본다. 워크스페이스 전환 UI는 존재하지 않는다.

### 3.3 대시보드

| 경로 | 화면 | 접근 |
|---|---|---|
| `/` | 대시보드 · 내 업무 탭 | 로그인 + 워크스페이스 소속 |
| `/?tab=all` | 대시보드 · 전체 탭 | **내가 Lead인 프로젝트 ≥ 1** 또는 WS Admin |

- `?tab=all` 진입 자격이 없으면 탭 자체를 렌더하지 않고, 직접 URL 접근 시 `?tab=mine` 으로 대체한다.
- 소속 프로젝트가 0개면 대시보드 대신 **온보딩 안내**를 렌더한다 (US-103). 별도 주소를 만들지 않는다 — 프로젝트가 생기면 자동으로 정상 대시보드가 된다.

### 3.4 내 업무

| 경로 | 화면 | 접근 |
|---|---|---|
| `/tasks` | 내 업무 보드 (상태 컬럼) | 로그인 |
| `/tasks?view=list` | 리스트 뷰 + 필터 | 로그인 |
| `/tasks?view=list&assignee=…&project=…&status=…&due=…` | 필터 적용 상태 | 로그인 |

- **필터·뷰 상태는 전부 쿼리스트링에 반영한다.** 새로고침·뒤로가기·공유에서 유지되어야 한다 (US-404 AC-5).
- 리스트 뷰의 `assignee` 필터는 **내가 속한 프로젝트 범위 안에서만** 동작한다 (US-504 AC-2).
- **여기에 사람 컬럼 보드는 없다** (D-006a). `?view=` 가 받는 값은 `board` | `list` 뿐이다.

### 3.5 프로젝트

| 경로 | 화면 | 접근 | 비고 |
|---|---|---|---|
| `/projects` | 프로젝트 목록 | 로그인 | 내가 속한 프로젝트. WS Admin은 전체 |
| `/projects?archived=1` | 보관된 프로젝트 | 로그인 | US-205 |
| `/projects/[id]` | 개요 | PJ Member 또는 WS Admin | 진행률·멤버·상태 요약 |
| `/projects/[id]/board` | **배정 보드** ⭐ | 〃 | 데스크톱 전용 (D-026). 모바일은 읽기전용 리스트 |
| `/projects/[id]/board?filter=review\|delayed\|in_progress` | 필터 적용 | 〃 | US-404 |
| `/projects/[id]/docs` | 문서 링크 | 〃 | US-901 |
| `/projects/[id]/settings` | 프로젝트 설정 + 멤버 | **PJ Lead** | 비Lead 접근 시 `/projects/[id]` 로 되돌림 |

**프로젝트 생성**은 별도 페이지를 두지 않는다. `/projects` 에서 모달로 처리한다.
→ 입력이 **이름 하나뿐**(US-201 AC-2)이라 페이지를 만들 이유가 없다.

### 3.6 Task 상세

| 경로 | 화면 | 접근 |
|---|---|---|
| `/tasks/[taskId]` | Task 상세 | 해당 프로젝트의 PJ Member 또는 WS Admin |

**하나의 주소, 두 가지 표현** — §5에서 상술.

### 3.7 알림

| 경로 | 화면 | 접근 |
|---|---|---|
| `/notifications` | 알림 전체 목록 | 로그인 |

- 데스크톱에서는 헤더 벨 → **드롭다운**이 주 경로이고, 이 페이지는 "전체 보기"다.
- **모바일에서는 이 페이지가 주 경로**다 (하단 탭에 위치, §6).

### 3.8 설정

| 경로 | 화면 | 접근 |
|---|---|---|
| `/settings` | 프로필 (이름·아바타) | 로그인 |
| `/settings/members` | 워크스페이스 멤버 · 초대 관리 | 조회는 전원, **변경은 WS Admin** |
| `/settings/notifications` | 알림 권한 상태 · 켜기 | 로그인 |
| `/settings/workspace` | 워크스페이스 이름 · 양도 | **WS Owner** |

> 💡 `/settings/members` 를 **조회는 전원에게 연 이유**: Foundation D-002에서 `Team` 메뉴를 없앤 대신, "우리 회사에 누가 있지"를 볼 곳은 남겨야 한다. 없으면 그 질문이 카톡으로 나간다.

┌─────────────┬──────────────────────────────────────────┐
│             │  [프로젝트명 / 화면명]      🔔 3   (아바타) │
│  core_task  ├──────────────────────────────────────────┤
│             │                                          │
│  🏠 대시보드 │                                          │
│  📋 내 업무  │              메인 영역                     │
│  📁 프로젝트 │                                          │
│             │                                          │
│  ─────────  │                                          │
│  최근 프로젝트│                                          │
│   · 마케팅몬스터                                         │
│   · 리뉴얼   │                                          │
│             │                                          │
│  ⚙️ 설정     │                                          │
└─────────────┴──────────────────────────────────────────┘
```

### 사이드바 = 3개 + 설정 (D-013 이행)

| | 라벨 | 경로 |
|---|---|---|
| 🏠 | 대시보드 | `/` |
| 📋 | **내 업무** | `/tasks` |
| 📁 | 프로젝트 | `/projects` |
| ⚙️ | 설정 | `/settings` (하단 고정) |

> ⚠️ **D-013은 "4개"라고 적었지만 설정을 하단에 분리하면 상단은 3개다.** 개수를 줄인 게 아니라 배치가 다르다. 설정은 매일 가는 곳이 아니므로 상단 목록에서 빼서 시각적 소음을 줄인다.

> ✅ **`Tasks` 가 아니라 `내 업무` 다 (D-028).**
> 프로젝트 안에도 "업무" 탭이 있어서 같은 이름이면 혼동된다. 그리고 이 메뉴의 기본이자 90% 용도는 **본인 업무**다 (US-501 AC-1). 이름이 용도를 말해야 한다.

### 최근 프로젝트 바로가기

사이드바 하단에 **최근 방문 프로젝트 3개**를 노출한다.
→ 근거: 배정 보드(`/projects/[id]/board`)가 Lead의 최고 빈도 화면인데, 기본 경로가 `프로젝트 목록 → 프로젝트 → 보드 탭` 으로 **3클릭**이다. Foundation §2 *"자주 하는 일일수록 화면 깊이가 얕아야 한다"* 위반이다. 이 바로가기로 **1클릭**이 된다.

### 프로젝트 내부 탭 = 4개

```
[ 개요 ] [ 업무 ] [ 문서 ] [ 설정 ]
```

| 탭 | 경로 | 접근 |
|---|---|---|
| 개요 | `/projects/[id]` | PJ Member |
| **업무** | `/projects/[id]/board` | PJ Member (드래그는 Lead만) |
| 문서 | `/projects/[id]/docs` | PJ Member |
| 설정 | `/projects/[id]/settings` | **PJ Lead만** — 아니면 탭 자체가 안 보임 |

**Foundation §5의 원문 탭 7개에서 이렇게 줄었다.**

| 원문 탭 | v1 처리 |
|---|---|
| 개요 | ✅ 유지 |
| 일정 | ❌ Calendar가 v1.1이므로 제외 |
| Tasks | ✅ `업무` 로 유지 |
| Meetings | ❌ v1.1 |
| Documents | ✅ `문서` 로 유지 |
| 팀원 | 🔀 **`설정` 에 흡수.** 멤버 *조회*는 개요의 아바타 목록으로 충분하고 (US-203 AC-1), *관리*는 Lead만 하는 일이라 설정이 맞다. 탭 하나를 아낀다 |
| 설정 | ✅ 유지 (+ 멤버 관리 포함) |

## 5. Task 상세 — 하나의 주소, 두 가지 표현 🔑

**이 문서에서 가장 중요한 IA 결정이다.**

Task 상세는 **어디서 열든 `/tasks/[taskId]`** 라는 같은 주소를 갖는다. 다만 **어떻게 도달했는가**에 따라 표현이 달라진다.

| 진입 경로 | 표현 | 이유 |
|---|---|---|
| 보드/리스트에서 **카드 클릭** | **오른쪽 사이드 패널** (뒤에 보드가 그대로 보임) | 보드 맥락을 잃지 않는다 (§1-2) |
| **푸시 알림** 클릭 | **전체 페이지** | 뒤에 보여줄 맥락이 없다 |
| **URL 직접 입력 / 공유 링크** | **전체 페이지** | 〃 |
| **모바일** (모든 경로) | **전체 페이지** | 화면 폭에 패널이 들어갈 자리가 없다 |

**동작 규칙**
1. 패널이 열려도 **주소는 `/tasks/[taskId]` 로 바뀐다.** 브라우저 뒤로가기 = 패널 닫기.
2. 패널 상태에서 **새로고침하면 전체 페이지**로 열린다. (뒤의 보드 상태를 복원할 수 없으므로 정직하게 전체 페이지가 맞다)
3. 패널에서 `ESC` = 닫기 = 뒤로가기.
4. 전체 페이지에는 **"← 프로젝트 보드로"** 링크를 둔다. 알림으로 들어온 사람이 맥락을 찾아갈 경로다.

> **구현 메모 (D-042):** react-router 의 **`location.state.backgroundLocation`** 패턴으로 구현한다.
>
> ```tsx
> const bg = location.state?.backgroundLocation
>
> // 항상 렌더: bg 가 있으면 "뒤에 있던 화면"을 그린다
> <Routes location={bg || location}>
>   <Route path="/projects/:id/board" element={<Board />} />
>   <Route path="/tasks/:taskId"      element={<TaskPage />} />   {/* 전체 페이지 */}
> </Routes>
>
> // bg 가 있을 때만 그 위에 패널을 얹는다
> {bg && (
>   <Routes>
>     <Route path="/tasks/:taskId" element={<TaskPanel />} />     {/* 패널 */}
>   </Routes>
> )}
> ```
>
> **`backgroundLocation` 이 곧 "어디서 왔는가" 다.** 보드에서 카드를 클릭할 때만 이 state를 실어 보내므로,
> 푸시 알림·직접 URL·새로고침은 자동으로 전체 페이지가 된다 — 위 표의 규칙이 코드에 그대로 대응한다.

**같은 규칙을 적용하는 다른 화면**

| 화면 | 주소 | 표현 |
|---|---|---|
| 프로젝트 생성 | `/projects?new=1` | 모달 |
| 멤버 추가 | `/projects/[id]/settings?add=1` | 모달 |
| 마감일 팝오버 (US-304) | **주소 없음** | 드롭 직후 인라인 팝오버 — 화면이 아니라 상호작용이다 |

## 6. 모바일 내비게이션 — 축소판이 아니다

**사이드바를 햄버거로 접지 않는다.** 모바일 사용 시나리오가 데스크톱과 다르기 때문이다.

> Foundation §2: *"출근길에 '오늘 뭐 하지'를 폰으로 본다."*
> 모바일에서 하는 일은 사실상 **① 내 업무 확인 ② 상태 변경 ③ 알림 확인** 세 가지다.

### 하단 탭바 4개

```
┌──────────────────────────────────────┐
│                                      │
│           메인 영역                    │
│                                      │
├──────────────────────────────────────┤
│  🏠 홈    📋 내 업무   🔔 알림   ⚙️ 더보기 │
└──────────────────────────────────────┘
```

| 탭 | 경로 | 근거 |
|---|---|---|
| 🏠 홈 | `/` | 오늘 할 일 |
| 📋 내 업무 | `/tasks` | **모바일의 주 화면** (US-505) |
| 🔔 알림 | `/notifications` | 배정·리뷰요청이 핵심 트리거 (US-801) |
| ⚙️ 더보기 | `/more` | 프로젝트 목록 · 설정 · 프로필 |

**`프로젝트`가 하단 탭에 없는 이유:** 모바일에서 프로젝트 관리(배정·멤버·설정)는 하지 않는다. 배정 보드는 데스크톱 전용(D-026)이고, 프로젝트 조회는 `더보기` 로 충분하다. **탭 4개는 지키고, 안 쓰는 걸 뺀다.**

### 모바일에서 달라지는 화면

| 화면 | 데스크톱 | 모바일 |
|---|---|---|
| 내 업무 | 4컬럼 칸반 (드래그) | **상태 탭 + 세로 리스트 + 액션 버튼** (US-505) |
| 배정 보드 | 사람 컬럼 (드래그 배정) | **읽기 전용 리스트.** "배정은 PC에서 해주세요" 안내 |
| Task 상세 | 사이드 패널 | 전체 페이지 |
| 대시보드 | 위젯 그리드 | 위젯 세로 스택 |
| 알림 | 헤더 벨 드롭다운 | **전용 탭** |

## 7. 라우트별 접근 제어 요약

| 경로 패턴 | 필요 조건 | 실패 시 |
|---|---|---|
| `/login`, `/signup`, `/invite/*` | — | 로그인 상태면 `/` 로 |
| `/onboarding/workspace` | 로그인 | 워크스페이스 있으면 `/` 로 |
| `/`, `/tasks*`, `/projects`, `/notifications`, `/settings` | 로그인 + WS 소속 | `/login` 또는 `/onboarding/workspace` |
| `/?tab=all` | Lead 프로젝트 ≥1 또는 WS Admin | `?tab=mine` 으로 대체 |
| `/projects/[id]*` | PJ Member 또는 WS Admin | **404** |
| `/projects/[id]/settings` | PJ Lead 또는 WS Admin | `/projects/[id]` 로 |
| `/tasks/[taskId]` | 그 Task가 속한 PJ의 Member 또는 WS Admin | **404** |
| `/settings/members` (변경 액션) | WS Admin | 액션 미노출 + API 403 |
| `/settings/workspace` | WS Owner | `/settings` 로 |

**403이 아니라 404를 쓰는 이유 (§1-5)**
403은 *"이 프로젝트는 존재하지만 넌 못 본다"* 를 알려준다. 프로젝트 이름을 몰라도 ID를 훑으면 **몇 개가 있는지가 새어나간다.** 소규모 회사에서는 이것만으로도 정보다.
→ **UI 리다이렉트는 편의일 뿐이고, 실제 차단은 RLS에서 한다.** UI 숨김을 보안으로 신뢰하지 않는다 (PRD §7).

## 8. 화면별 빈 상태 (Empty State)

> Foundation §2: *"빈 화면을 방치하지 않는다. 첫날 텅 빈 대시보드는 이탈의 1순위 원인이다."*

**모든 빈 상태는 [상황 설명 + 다음 행동 버튼] 두 줄로 구성한다.** 회색 박스나 "데이터가 없습니다"는 금지한다.

| 화면 | 조건 | 문구 | 행동 |
|---|---|---|---|
| 대시보드 | 프로젝트 0개 · WS Admin | "첫 프로젝트를 만들어보세요" | 프로젝트 만들기 |
| 대시보드 | 프로젝트 0개 · Member | "아직 참여 중인 프로젝트가 없어요" | 관리자에게 요청 안내 |
| 대시보드 · 오늘 할 일 | 0건 | "오늘 할 일이 없어요" | 내 업무 보기 |
| 대시보드 · 리뷰 대기 | 0건 | "확인 기다리는 업무가 없어요 👍" | — (좋은 상태다) |
| 대시보드 · 지연 업무 | 0건 | "지연된 업무가 없어요 👍" | — |
| 내 업무 | 배정된 업무 0건 | "아직 배정된 업무가 없어요" | 업무 만들기 |
| 프로젝트 목록 | 0개 | 위와 동일 | |
| 배정 보드 | Task 0건 | "첫 업무를 만들어보세요" | 인라인 생성 포커스 |
| 배정 보드 · 미배정 컬럼 | 0건 | "미배정 업무가 없어요" | — |
| 배정 보드 · 담당자 컬럼 | 0건 | "여기로 카드를 끌어다 놓으세요" | (드롭 안내) |
| 문서 | 0개 | "Notion·Figma 링크를 모아두세요" | 문서 추가 |
| 알림 | 0건 | "새 알림이 없어요" | — |
| 프로젝트 멤버 | 본인만 | "함께 일할 팀원을 추가하세요" | 멤버 추가 |

> 💡 **"👍" 를 붙인 항목들이 중요하다.** 리뷰 대기 0건과 지연 0건은 *비어 있어서 아쉬운 상태*가 아니라 **달성한 상태**다. 여기에 "추가하기" 버튼을 두면 제품이 사용자를 오해하게 만든다.
